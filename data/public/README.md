# Published data contract — v1.0

These CSVs are a **published interface**, not a by-product of the report.
Anything outside this repository reads from here: a Google Sheet feeding a
Tableau Public dashboard, a Power BI web query, or whatever gets added later.

They are regenerated on every run of the weekly workflow and committed, so
each file is always the latest 28-day window and the raw URL is stable:

```
https://raw.githubusercontent.com/damondrc/ga4-reporting-automation/main/data/public/<file>.csv
```

## Why this exists

`report/data/*.csv` mirrors whatever the GA4 Data API returned: camelCase, raw
metric names, free to change the moment a query changes. That is fine for an
internal artefact and unusable as an interface.

The problem with dashboards reading internal files is the failure mode. A
renamed column does not raise an error anywhere — the chart keeps rendering
with the last values it cached, and nobody notices for weeks. A published
contract makes the boundary explicit: this side may not change silently.

## The rules

1. **Stable names.** snake_case, decoupled from GA4's own naming. If Google
   renames a metric, the mapping absorbs it and consumers never see it.
2. **Append-only.** Columns are never renamed, removed or reordered — only
   added at the end. Same discipline the upstream event names follow.
3. **Raw values.** Rates are decimals (`0.774`), not `"77.4%"`. Dates are ISO.
   Formatting is the dashboard's job; a formatted number is a dead number.
4. **Counts are integers.**
5. **Breaking changes get a new version.** A change that cannot be additive
   means `data/public/v2/` alongside this one, kept until consumers migrate.

## Files

### `daily_kpis.csv`
One row per day in the window. Days with no activity are present with zeros —
the API omits them, and a missing row draws a slope across a silent stretch.

| Column | Type | Notes |
|---|---|---|
| `date` | date | `YYYY-MM-DD` |
| `sessions` | int | |
| `users` | int | Total users |
| `page_views` | int | |
| `events` | int | All events, including the non-funnel ones |

### `funnel.csv`
The signup funnel in journey order. Five rows, always — a step with no data is
a zero, never a missing row.

| Column | Type | Notes |
|---|---|---|
| `step_number` | int | 1–5, the journey order. Sort by this, never by volume |
| `step_name` | string | Human label |
| `event_name` | string | GA4 event, as defined in the measurement plan |
| `event_count` | int | Events, **not** distinct users progressing |
| `pct_of_previous` | float | 0–1. Step 1 is 1.0 by definition |
| `pct_of_entry` | float | 0–1, relative to step 1 |

### `by_channel.csv`

| Column | Type | Notes |
|---|---|---|
| `source` | string | Synthetic traffic appears as `traffic-sim` |
| `medium` | string | Synthetic traffic appears as `synthetic` |
| `sessions` | int | |
| `users` | int | |

### `by_device.csv`

| Column | Type | Notes |
|---|---|---|
| `device` | string | `desktop` / `mobile` / `tablet` |
| `sessions` | int | |
| `engagement_rate` | float | 0–1 |

### `by_plan.csv`
Sign-ups split by the `plan_id` custom dimension. May be absent or partial:
GA4 custom dimensions are not retroactive, so it only covers sign-ups collected
after the dimension was registered.

| Column | Type | Notes |
|---|---|---|
| `plan` | string | `Starter` / `Pro` / `Business` |
| `signups` | int | |
| `share` | float | 0–1, share of total sign-ups |

### `meta.csv`
One row. Read this before trusting the rest — a file timestamp is rewritten by
git on checkout and says nothing about when the data was pulled.

| Column | Type | Notes |
|---|---|---|
| `schema_version` | string | `1.0` |
| `generated_at_utc` | datetime | ISO 8601, UTC |
| `window_start` / `window_end` | date | Reporting window covered |
| `window_days` | int | Window length |
| `source` | string | `GA4 Data API` |

## Consuming it

**Google Sheets** (the bridge for Tableau Public, which can refresh from a
Sheet on a schedule but not from a bare CSV URL) — one formula per tab:

```
=IMPORTDATA("https://raw.githubusercontent.com/damondrc/ga4-reporting-automation/main/data/public/daily_kpis.csv")
```

**Power BI** — Get data → Web → the same raw URL. It is an anonymous public
source, so scheduled refresh needs no gateway.

**Anything else** — the URL is a plain CSV over HTTPS.

## About the numbers

This is a demo property with low volume, and a share of its traffic is
generated by a [synthetic traffic simulator](https://github.com/damondrc/portfolio-analytics/tree/main/bot)
that identifies itself as `traffic-sim / synthetic` precisely so it can be
filtered out. The point of this dataset is a pipeline that runs unattended,
not the size of the numbers.
